# Game data

Two hand-curated JSON sources plus one generated geometry artifact, all under
`src/assets/data/` and loaded at build time (not fetched at runtime).

## Files

- `routes.json` — one entry per national route (RN):
  ```json
  { "routes": [
    { "id": "rn-1", "full_name": "Autopista Dr. Ricardo Balbín",
      "length_km": 53.42, "description": "…",
      "cities": ["caba/buenos-aires", "buenos-aires/avellaneda", "…"] }
  ]}
  ```
  `full_name` is omitted when the source only had a generic placeholder
  (`"Ruta Nacional N"`) — `GameUiPresenter`/`GameFlowCoordinator` already fall
  back to `route_name`/`"Ruta N"` when it's missing. `cities` is the ordered
  list of city ids the player types, resolved against `cities.json`. A route
  with no curated cities yet (e.g. `rn-173`, `rn-175`) has `cities: []`.

- `cities.json` — the shared, deduplicated city catalog (cities can belong to
  multiple routes):
  ```json
  { "cities": [
    { "id": "neuquen/puente-colon-cura", "name": "Puente Colón Curá",
      "typing": "puente colon cura", "lat": -40.436, "lon": -70.65,
      "province": "Neuquén", "tier": "minor", "kind": "bridge" }
  ]}
  ```
  `tier` is a size/importance bucket (`major`, `medium`, `minor`). `kind` is
  optional and describes a role rather than a size (`bridge`, `ferry`,
  `detour`, `endpoint`); when present, `tier` is always `"minor"`.

- `routes_render.json` + `routes_render.bin` — generated by
  `data/simplify_geometries.py`, loaded by `src/js/data/RouteGeometryStore.ts`.
  Do not hand-edit; regenerate instead (see below).

## Id rules

- **Route id**: `rn-<n>`, no zero padding (`rn-1`, not `rn-0001`). The display
  number (`route_number`) and short name (`route_name`, `"RN <n>"`) are
  derived from the id at load time in `RoutesController`, not stored.
- **City id**: `<province-slug>/<city-slug>`, both kebab-case ASCII (lowercase,
  accents stripped, non-alphanumeric runs collapsed to a single `-`). The
  province slug must match `slugify(province)`, with one fixed exception: the
  Ciudad Autónoma de Buenos Aires (displayed as
  `"Ciudad Autónoma de Buenos Aires"`) uses the short-hand slug `caba` instead
  of its literal slug. The historical ferry crossing (no real Argentine
  province) is filed under `tierra-del-fuego/estrecho-de-magallanes`.
- **Province**: canonical display names only — no `"N/A"`, no parenthetical
  qualifiers like the old `"Buenos Aires (CABA)"`.
- `typing` must be lowercase and accent-free; it should normally match what
  you'd get by stripping accents/punctuation from `name`, but a handful of
  entries intentionally diverge (shortened landmark names, one city with a
  literal `.` in `typing`) — the validator warns on these rather than failing.

## Regenerating geometry

The raw DNV (Argentina's road authority) export lives at
`data/raw/national_routes_geometries.json` (20 MB, not imported by the app —
kept only as the simplifier's input). To rebuild `routes_render.{json,bin}`
from it:

```
python3 data/simplify_geometries.py data/raw/national_routes_geometries.json src/assets/data
```

To rebuild from a fresh DNV WFS export instead (regenerates `routes.json`'s
non-curated fields and `data/raw/national_routes_geometries.json`, preserving
any existing `full_name`/`description`/`cities` already curated at that route
id — see the script's docstring):

```
python3 data/build_national_routes.py <input_ows.json> src/assets/data/routes.json
python3 data/simplify_geometries.py data/raw/national_routes_geometries.json src/assets/data
```

`cities` are never sourced from the DNV export — they're curated by hand
against `cities.json` after the fact.

## Provenance note

RN3's city list (`rn-3`) was hand-scaffolded against Wikipedia and the
ACA/Secretaría de Turismo RN3 survey (Feb–Mar 2026); coordinates are
approximate and haven't been cross-checked against the Georef API
(`apis.datos.gob.ar/georef`) or BAHRA.

## Validating

```
python3 data/validate_data.py
```

Checks `routes.json`, `cities.json` and `routes_render.json` for: unique route
and city ids; every route's `cities` entries resolve to a real city; every
route has a `routes_render.json` entry; id formats (`rn-<n>`,
`<province-slug>/<city-slug>`, city id prefix matching `slugify(province)`);
allowed `tier`/`kind` values; `typing` lowercase and accent-free. Exits
non-zero only on those hard errors.

It also prints (non-fatal) content-gap warnings: routes with fewer than 2
cities, orphan cities not referenced by any route, and `typing`/`name`
mismatches — these are known, pre-existing gaps to fill in by hand, not
integrity bugs.
